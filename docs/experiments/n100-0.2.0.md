# 0.2.0 N100 개발 진단

대상은 N100 내장 Intel UHD GPU다. 현재 빌드 장비는 Core Ultra 9 285K / RTX 5080이며
N100 실측 장비가 아니다. 현재 PC 지연을 N100 성능으로 표현하지 않는다.

로그 132장·1,096개 객체는 모델 가중치 학습에서 제외한다. 이번 요청에서 해당 로그는
후보·전역 검출 임계값·실행 정책을 비교하는 개발 진단에 사용되므로 독립 validation/test가 아니다.
초기 설정의 calibration 미사용 문구와 달리 후속 개발에서는 검출 정책 선택에 사용했다.
학습 미사용과 정책 선택 미사용은 서로 다른 조건이며 이 차이를 보고서에 보존한다.
`bread_dataset/multi_object_scenes`는 후보 선택에 사용하지 않는다.

판정은 객체별 정답 APPROVED 1,042개 이상, 오승인 0건, 미검출 0건과 실제 HTTP p95 200ms
이하를 모두 요구한다. IMAGE_RECAPTURE와 ERROR도 전체 GT 분모에 포함하며 미검출을 숨기지
않는다. 추가 박스, 중복 승인, UNKNOWN, SEGMENT_RECAPTURE를 별도로 보고한다.

기준 모델, 원본 재생 모델, 가림 합성 재학습, 다른 seed, 회전, 해상도 변경, 타일 검출 및
D-FINE 후보를 비교한다. 낮은 임계값에서 proposal recall만 높아진 것은 인식률로 간주하지
않으며, Worker HTTP 결과로 다시 평가한다. 최종 선택과 측정값은 별도 고정 보고서에 기록한다.

가림 재학습은 원본 302장 전부를 epoch마다 8회, 총 64회 소비했다. 검수된 원본 cutout과
허용 배경만으로 1,200장을 합성했다. 빈 장면 240장, 양성 장면 960장, 장면당 4~12개,
최소 가시 면적 20%, 크기 범위 16~40%다. 모든 합성 장면과 객체는 부모 원본 SHA-256을
가지며 로그 이미지 픽셀·정답은 학습 입력에 포함되지 않는다. 분류기와 Catalog는 기준 모델을
유지한다. 낮은 점수의 누락 후보를 무조건 승인하지 않는다.

0.2.0의 선택적 지역 재촬영 정책은 metadata의
`quality.detector_segment_recapture_score_threshold` 미만인 검출 ROI를
`SEGMENT_RECAPTURE`로 반환한다. 분류기가 높은 확신을 보여도 승인하지 않는다.
기존 품질·경계·다중 객체 거부가 우선하고, 포함 중복 검토의 UNKNOWN 정책도 유지한다.
촬영 전체 hard 품질 거부의 IMAGE_RECAPTURE 조기 종료는 그대로 유지한다.
과거 Runtime에서는 새 필드가 없으므로 기존 동작을 유지한다.

N100 실행 순서는 ORT CPU detector(2 threads) → OpenVINO GPU primary/detail → 선택적 CPU
Frozen ViT verifier(4 threads) → CPU 후처리다. GPU 미지원·초기화 실패 시 명시적으로 CPU로
시작한다. GPU session 실행 장애가
발생한 요청은 ERROR이며, CPU Runtime 재구성이 성공한 다음 요청부터 CPU를 사용한다.
재구성 중 또는 실패 후 readiness는 503이다. 전환을 구조화 로그에 남기고 readiness provider도
갱신한다. checksum 손상이나 일반 모델 오류는 GPU 장애로 재해석하지 않는다.

N100 배포에는 ONNX Runtime OpenVINO 1.24.1과 OpenVINO 2025.4.1을 고정한다.
GPU는 LATENCY/1 stream/FP32로 구성한다. 실제 Intel UHD에서의 호환성·속도는 대상 장비에서
별도 측정해야 한다. CPU/CUDA 실행과 공개 `/v1/scan` 상태·오류 schema는 유지한다.

N100에는 `BixolonBakeryAIScannerLite-0.2.0-N100-Setup.exe` 또는 N100 Portable을 사용한다.
일반 CPU 설치본과 같은 제품 ID이므로 장비에 맞는 한 가지 설치본을 선택한다.
외부 연동은 N100 Worker ZIP을 풀고 `RUN-N100-WORKER.cmd`를 실행한다. 기본 주소는
`http://127.0.0.1:8000`이며, GPU 가속 사용 여부는 `/health/ready`의 provider와 Worker 로그로
확인한다. CPU fallback 결과를 GPU 성능으로 해석하지 않는다.

실측은 다른 학습·빌드 작업을 중지하고 Worker 준비가 끝난 다음 아래 명령으로 실행한다.
이미지 폴더에는 원본 로그 132장만 둔다. 파일 읽기를 측정 전에 완료하고, warmup 10회 이후
132장 전체를 3회 측정한다. HTTP 오류 응답도 저장한다. 장비 정보·readiness·각 응답과 HTTP
왕복 시간이 사용자 로컬 데이터의 `BIXOLON/Benchmarks` 아래에 저장된다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\measure-n100.ps1 -ImageDirectory C:\data\log132
```

이 도구의 응답 기록만으로 정확도를 판정하지 않는다. 고정 GT와 클래스 무관 bbox IoU ≥0.5
일대일 대응으로 정확도·오승인·미검출을 집계해야 한다. 오류·재촬영을 분모에서 빼지 않는다.
Checksum은 파일 변경·손상을 탐지하며 발행자 진위 인증은 제공하지 않는다.
