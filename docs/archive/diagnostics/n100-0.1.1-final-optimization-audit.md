# N100 `0.1.1` 최종 최적화 진단

기준일은 2026-08-20입니다. 이 문서는 실제 N100 현장 결과가 돌아오기 전에 수행한 마지막 로컬
진단을 기록합니다. 측정 장비는 Intel Core Ultra 9 285K이며 N100 성능이나 SLA를 증명하지
않습니다.

## 선택한 실행 경로

- 제품 버전: `0.1.1`
- 모델 graph와 weight: 변경 없음
- Detector: `production` primary, selected count가 6이고 `uncertain`, 최소 점수 `≤0.5` 또는
  `≥0.87`일 때만 `fold1` secondary 실행
- Provider: `OpenVINOExecutionProvider`, CPU
- Thread: detector `1 worker × 4 threads`, embedder `4 threads`
- 후보 ZIP: `artifacts/handoff/n100-0.1.1-candidate-20260820.zip`

300장 개발 재평가에서 detector FN/FP와 승인 오인은 모두 0건이었고 OpenVINO 평균/p95/p99는
169.53/228.13/234.90ms였습니다. CPU와 OpenVINO의 공개 판정은 일치했습니다.

## 남은 병목

개발 이미지 앞 100장의 OpenVINO 단계 측정은 다음과 같습니다. `processing`은 decode를 제외한
Pipeline 시간입니다.

| 단계 | 평균 | p95 |
|---|---:|---:|
| JPEG decode | 24.40ms | 29.94ms |
| Detector | 35.78ms | 40.42ms |
| Classifier 전체 | 96.44ms | 122.46ms |
| 그중 Embedder ONNX | 88.91ms | 112.03ms |
| Pipeline processing | 131.42ms | 157.98ms |

Classifier의 crop, normalization과 Catalog 판정은 평균 약 8.08ms이므로 추가 이미지 복사 제거만으로
얻을 수 있는 폭은 작습니다. 모델 변경 없이 남은 주요 비용은 Embedder ONNX 추론입니다.

## 폐기한 추가 후보

### Classifier ROI 병렬 세션

여러 ROI를 두 OpenVINO 세션과 `2×2` thread로 나누면 Classifier 평균/p95가
96.44/122.46ms에서 109.69/141.36ms로 악화됐습니다. 세션 scheduling 비용과 각 2-thread
convolution의 비효율 때문에 폐기했습니다.

### OpenVINO graph·stream·precision option

ORT graph optimization 비활성화, `PERFORMANCE_HINT=LATENCY`, `NUM_STREAMS=1`,
`EXECUTION_MODE_HINT=ACCURACY|PERFORMANCE`, 명시적 `f32`를 비교했습니다. Embedder batch 5의 현재
평균은 106.93ms였고 다른 설정은 107.68~108.78ms로 개선되지 않았습니다. `NUM_STREAMS=2|4`와
동시 ROI 요청도 각각 약 124.45ms와 162.51ms로 느려 폐기했습니다.

### JPEG draft 700

`jpeg_draft_size`를 1000에서 700으로 낮추면 3024×4032 JPEG의 decode 크기가 1512×2016에서
756×1008로 줄어듭니다. 그러나 300장 평가에서 FN 1건, FP 2건이 발생했고 OpenVINO p95도
231.36ms로 선택 후보의 228.13ms보다 느렸습니다. 정확도와 속도 모두 이점이 없어 폐기했습니다.

## 남은 확인

로컬 결과와 기존 `0.0.2` N100 배율을 단순 적용하면 새 후보 p95는 약 1초 경계에 있습니다. 이는
추정값일 뿐이므로 `RUN-N100-TEST.cmd`가 생성하는 실제 `n100-0.1.1-result.json`의 OpenVINO 평균과
p95가 모두 1,000ms 이내인지 확인하기 전에는 목표 달성이나 최종 Setup 생성을 확정하지 않습니다.
