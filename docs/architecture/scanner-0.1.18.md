# BIXOLON Bakery AI Scanner 0.1.18

모델을 바꾸는 세 후보가 회귀 검증을 통과하지 못해 **0.1.17 모델·Catalog·정책을 유지**한다.
0.1.18의 실행 변경은 CPU에서 각 ONNX session의 idle spinning을 끄는 것이다.
설치본·portable·Lite·Worker·Store Model은0.1.18, Flutter build21, SDK Core는1.1.2다.

로그의 오승인4건은 품목 오분류가 아니라 GT와 대응하지 않는 부분·추가 검출 승인이다.
확정 bbox와 품목을 바꾸지 않았다. D-FINE dense는 오승인을0으로 줄였지만 정답 승인24개 감소,
basic은21개 감소했다. SSDLite 재생학습은 로그 정답2개 증가·오승인1개 감소였지만 원본에서
새 오승인1개가 생겨 기각했다. 학습에는 원본302장과 합성1,200장만 소비됐고 원본별96회 이력을 보존한다.

CPU 변경은 로그396회, 원본906회 상태·품목 순위가 모두 같았다. 로그의 정답 승인은
1,082/1,096(98.72%)·오승인4건, 원본은645/649(99.38%)·오승인0건이다.
다른 Lite Worker의 시작·종료가 겹친 측정은 보존하고 제외했으며 AB,BA,AB 교차 측정의
간섭 없는 세 반복에서 p95가약59~64% 감소했다. 기준 장비는 Intel Core Ultra9 285K다.
HTTP는 업로드·디코드·모든 추론·응답 처리를 포함하고 시작 로딩·요청 전 파일 읽기는 제외한다.

로그는 원본과 SHA-256 중복0개지만 같은 실물 컬렉션이다. 독립 실물이나 다른 매장의 일반화
성능으로 표현하지 않는다. 로그·검수 산출물·최종 benchmark 이미지는 새 학습에서 접근을 차단했다.
세 후보와 CPU 변경의 설정·입력·출력·소비 이력·명령은
[실험 기록](../experiments/log-improvement-0.1.18.md)에 보존한다.

CPU+GPU 혼합 및 초기화 CPU fallback 코드는 유지하지만 기본 배포에서는 비활성이다.
CPU 설치본/Lite/SDK와 CUDA portable을 별도로 제공한다. 요청 실행 오류는 ERROR로 유지한다.
checksum은 파일 손상·변경 탐지이며 발행자 인증은 제공하지 않는다.

최종 배포 EXE의 고정300장 회귀 결과와 배포 검증은 `artifacts/distributions/0.1.18/reports`에 기록한다.
기존99%·오승인0 목표 달성을 자동으로 주장하지 않는다. 최종 결과로 모델·임계값을 재조정하지 않는다.

## 실제 배포 EXE 비교 결과

고정 300장·1,410 GT는 CPU·CUDA의 각 3회에서 정답 승인 1,352개(95.89%)·오승인 4건,
완전 성공 이미지 253/300장으로 두 버전이 같았다. 버전 간 상태·품목 순위는 provider별 900회,
신버전 CPU/CUDA도 900회 일치했다. 정답 승인 99%·오승인 0의 동시 목표는 미달이다.

CPU HTTP p95는 0.1.17의 302.53/331.87/307.88ms에서 0.1.18의
170.49/172.30/169.96ms로 약 44~48% 감소했다. 배포 CPU EXE의 학습 미사용 로그 p95는
180.41/176.88/181.28ms이며 396회 상태·품목 순위도 같았다. 이 환경의 p95 결과이지
모든 요청이 300ms 이하라는 뜻은 아니다. p50·p99·최댓값과 난이도별 결과도 보고서에 남겼다.

CUDA 최초 block 비교 중 한 반복은 p95가 10.6% 증가하여 AB,BA,AB 순서의 추가 진단을
수행했다. 최초 결과와 추가 결과를 모두 보고하며 모델이나 정책을 다시 조정하지 않았다.
추가 세 비교의 p95 신/구 비율은 0.9833/1.0079/0.9816이고 상태·품목 순위도 모두 같았다.
이 추가 진단에서는 5%를 넘는 지연 증가가 반복되지 않았다.

전체 Python 1,159개, Flutter 일반 앱 193개·Lite 24개·SDK 6개, 세 analyze와 Ruff·diff 검사,
실제 CPU/CUDA Worker smoke를 통과했다. 설치 파일 2종·휴대형 3종·Worker·SDK·Store Model을
제공한다. 설치/제거 및 카메라 하드웨어의 실제 시험은 이번 범위에서 수행하지 않았다.
