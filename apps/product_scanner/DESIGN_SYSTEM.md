# BIXOLON Scanner 디자인 시스템

이 문서는 Windows 현장 검수자가 촬영, 상품 확인, 최종 확정을 빠르고 안전하게 수행하기 위한 UI 계약입니다. 구현의 기준 소스는 `lib/theme/app_tokens.dart`, `lib/theme/app_theme.dart`이며 화면별 임의 색상이나 크기를 추가하지 않습니다.

## 디자인 방향

- **한 화면, 한 핵심 행동:** 현재 단계에서 가장 중요한 행동만 Primary로 표시합니다.
- **검수 장비다운 정밀함:** 표면과 경계는 중립적으로 유지하고 선택, 포커스, 핵심 행동에만 BIXOLON Orange를 사용합니다.
- **의미 있는 브랜드 표현:** BIXOLON Orange는 핵심 행동과 선택·포커스에만 사용하고, 카메라 프리뷰 위에는 장식용 선이나 표식을 추가하지 않습니다.
- **색상에 의존하지 않는 상태:** 모든 상태는 색상과 함께 아이콘 및 한국어 문구로 표시합니다.
- **오류와 재촬영의 분리:** 시스템 장애인 `ERROR`와 모델 판정인 `RECAPTURE`를 같은 시각 또는 행동으로 표현하지 않습니다.

## 사용자 시나리오 계약

같은 화면을 정상 경로만으로 검증하지 않습니다. 아래 사용자가 각자 예측할 수 있고 복구 가능한 흐름을 가져야 완료된 UX로 봅니다.

| 사용자 | 대표 행동 | 완료 조건 |
| --- | --- | --- |
| 처음 사용하는 작업자 | 안내 문구와 Primary만 따라 촬영·재촬영·저장 | 버튼을 눌렀을 때 이름 그대로의 결과가 발생하고 다음 행동이 한 개로 보임 |
| 세부사항을 엄격히 확인하는 작업자 | 모든 reason code, 입력원, 오류 문구를 비교 | 원인·복구 동사·입력원 라벨이 일치하고 `ERROR`와 `RECAPTURE`가 섞이지 않음 |
| 중복 입력으로 오류를 유도하는 작업자 | 촬영·파일 선택·새로고침을 연타하고 처리 중 단축키 실행 | 비동기 작업은 한 번만 실행되고 완료 전 다른 입력이 상태를 덮어쓰지 않음 |
| 키보드·보조기기 사용자 | Tab·Enter·Space·단축키와 큰 글자로 전체 흐름 진행 | 포커스가 다음 실제 행동으로 이어지고 진행 상태는 단일 live region으로 전달됨 |

카메라 `RECAPTURE`는 `촬영 이미지 → 촬영 화면으로 돌아가기 → 라이브 카메라 → 촬영하기 → 촬영 중 → 분석 중` 순서를 지킵니다. `촬영 화면으로 돌아가기`는 세션과 이전 판정만 비우며 촬영 API를 호출하지 않습니다. 실제 `촬영하기`를 실행한 뒤에는 `capturing`을 busy 상태로 사용해 중복 촬영·이미지 선택·세션 초기화를 막습니다.

## 토큰

색상 토큰은 세 계층으로 관리합니다.

1. **원시 토큰 `AppPalette`:** 브랜드·중립·상태색의 고정값
2. **의미 토큰 `AppSemanticColors`:** `brand`, `surface`, `success`, `error`처럼 화면 맥락과 무관한 역할
3. **컴포넌트 토큰 `AppComponentColors`:** `selectionSurface`, `selectionOutline`, `actionBarSurface`, `toastSurface`, `focusRing`, `previewScrim`처럼 상호작용·표면 역할

화면 코드는 가능한 한 의미·컴포넌트 토큰을 사용합니다. 원시 토큰을 직접 사용해 새로운 선택색이나 피드백색을 만들지 않습니다. 타이포그래피는 `AppTypography`, 간격은 `AppSpacing`, 높이·반경·모션은 `AppDesignTokens`, 핵심 행동 문구는 `AppActionCopy`, 프리뷰 출처 문구는 `AppPreviewCopy`를 단일 구현 기준으로 사용합니다.

### BIXOLON 원본 가이드 대응

- 브랜드 원본값은 `BIXOLON_Brand_Guidelines_English_Apr26_V1.pdf`의 Orange `#EE7203`, Orange Tint `#F28E00·#F7AA4E`, 승인 중립색 `#000000·#3F3D3E·#878786·#AEAEAE·#F5F5F5`를 기준으로 확인합니다.
- UI 본문 Ink `#171717`과 Selection Surface `#FFF4E9`는 앱 접근성과 선택 피드백을 위한 파생 토큰이며 공식 로고나 브랜드 텍스트에 적용하지 않습니다.
- 공식 로고는 앱에서 재제작하지 않으며, `X` 기반 대각선을 카메라 프리뷰 오버레이로 사용하지 않습니다.

### 타이포그래피

Pretendard Variable을 기본으로 사용하고 미지원 환경에서는 `Segoe UI`, `Malgun Gothic`, `Arial` 순으로 대체합니다.
글꼴·크기·행간·굵기의 구현 기준은 `AppTypography`이며, 화면이 독자적인 `TextStyle`로 글꼴 상속을 끊지 않습니다.

| 역할 | 크기/행간 | 굵기 |
| --- | --- | --- |
| 화면 제목 | `24/32` | 700 |
| 섹션 제목 | `18/26` | 700 |
| 본문 | `16/24` | 400 |
| 보조 본문 | `14/20` | 400~700 |
| 캡션 | `12/18` | 400~700 |
| 컴팩트 필터·칩 | `13/20` | 600~700 |
| CTA | `15/20` | 700 |

굵기는 `regular 400`, `medium 500`, `semibold 600`, `bold 700`만 사용합니다. 화면 제목·섹션 제목·앱명·데이터 레이블 tracking도 `AppTypography`에 정의하며 화면 코드에서 `FontWeight`, 글자 크기, 자간 숫자를 직접 만들지 않습니다.

### 크기와 간격

- 간격은 `4, 8, 12, 16, 24, 32px`만 사용합니다.
- 공통 컴포넌트와 화면의 패딩·요소 간 간격은 숫자를 직접 복제하지 않고 `AppSpacing.x1/x2/x3/x4/x6/x8`에 연결합니다. 아이콘의 광학 크기와 모델 좌표는 간격 토큰 대상에서 제외합니다.
- 최소 조작 영역은 `44px`, 주요 행동은 `48px`, 목록 행은 `60px`, 상단·패널 헤더는 `60px`, 섹션·표 헤더는 `40px`, 고정 액션 바는 최소 `72px`입니다.
- 운영 레이아웃 수치는 `AppDesignTokens`와 `AppBreakpoints`에서 관리합니다. 스캔 결과 패널은 폭 `36%`, 최소 `440px`, 최대 `520px`, 선택 객체 검수 영역은 최대 높이이자 다수 객체에서 우선 확보할 높이 `340px`, Activity 검색창은 `320px`이며 스캔 적층 전환점은 `960px`입니다. 확인 대화상자 `dialogWidth 400px`, 빈 상태 `emptyStateMaxWidth 360px`, 진단 레이블 `metadataLabelWidth 88px`도 화면에서 숫자를 복제하지 않습니다.
- 헤더는 `60px`, 공식 SVG 로고는 `105×30px`, 텍스트 탭은 `112×52px`와 상단 여백 `8px`, Orange 기준선·선택 윤곽은 `navigationIndicatorThickness 3px`를 사용합니다. 비조작 상태 요소는 `compactVisualSize 32px`, 단계 탐색 중앙 레이블은 `stepNavigatorLabelWidth 52px`, 프리뷰 출처 칩은 최소 `previewLabelMinHeight 36px`와 `previewSourceMarkerSize 6px`를 사용합니다. 진행 표시는 문맥에 따라 `inline 20px`, `preview 24px`, `page 28px`로 구분하며 모두 `AppDesignTokens`에서 관리합니다. 콘텐츠가 커지면 상태 배지와 출처 칩은 고정 높이에 가두지 않고 최소 높이 위로 확장합니다.
- Windows의 적응형 compact 밀도로 크기가 줄지 않도록 `VisualDensity.standard`와 padded tap target을 명시합니다.
- 컨트롤 반경은 `8px`, 패널과 다이얼로그는 `12px`, 상태 배지는 `pillRadius`로 완전한 pill 형태를 유지합니다. 키보드 포커스는 `focusRingWidth 2px`, 선택 표면은 `selectionOutlineWidth 1.5px`를 Theme·필터·드롭다운·공통 선택 표면이 공유합니다. 선택 불가 콘텐츠는 `disabledContentOpacity 0.56`을 사용하고 배경·Semantics·pointer·keyboard 행동도 함께 비활성화합니다.
- 짧은 상태 전환은 `160ms`, 패널 전환은 `240ms`, 완료 피드백 유지 시간은 `3초`를 사용합니다. 상호작용 전환 곡선은 `AppMotion.interactionCurve`의 `easeOutCubic` 하나로 통일합니다. 전환 애니메이션은 시스템의 reduced motion 설정을 존중해 즉시 완료하고, 자동 스크롤은 점프하며, 불확정 진행 표시는 회전 대신 정적인 대기 아이콘으로 바뀝니다.

## 공통 컴포넌트

- **Brand mark:** 화면 헤더는 제공된 BIXOLON 공식 SVG 워드마크만 `105×30px`로 표시하고 임시 포커스 아이콘·인접 제품명을 반복하지 않습니다. Windows 제목은 `BIXOLON Scanner`를 유지하고 실행 파일 아이콘은 `tool/generate_windows_icon.py`로 관리합니다.
- **Navigation item:** `스캔·활동`은 아이콘 없는 텍스트 탭입니다. Workspace 헤더 위에 선택 탭만 Surface 면·Orange 상·좌·우 윤곽·Bold로 올리고, 비선택은 Muted Semibold로 낮춥니다. 포커스는 선택과 관계없이 Deep Orange 윤곽을 우선합니다.
- **Status badge:** 아이콘과 경계에는 상태색, 문구에는 Ink를 사용합니다. 장식이나 카테고리 분류에는 사용하지 않습니다.
- **Status priority:** 카메라 미연결은 스캔 화면에서 카메라 촬영을 막을 때만 Attention으로 표시합니다. 이미지 검수 중에는 `이미지 입력 · 카메라 미연결`, Activity에서는 `카메라 미연결`의 중립 배지로 낮추어 현재 작업과 경고가 경쟁하지 않게 합니다.
- **Panel header:** `headerHeight`의 최소 `60px` 안에 제목, 선택적 설명, 한정된 보조 행동만 포함합니다.
- **Section header:** `sectionHeaderHeight`의 최소 `40px`를 사용하며 목록 수량이나 표 컬럼처럼 다음 콘텐츠의 구조를 설명하는 데만 사용합니다.
- **Empty state:** 상황, 다음 행동 순서로 설명합니다. 모호한 사과 표현을 사용하지 않습니다.
- **Filter group:** 레이블과 동일한 선택 칩 간격·선택 면을 제공하며 입력원·기간처럼 상호 배타적인 필터에 사용합니다.
- **Search field:** 검색어가 없으면 `/` 단축키를, 입력 중이면 44px 이상의 지우기 행동을 같은 suffix 위치에 표시합니다. 검색·필터·정렬 중 하나라도 기본값이 아니면 인접한 `모두 초기화`로 전체 조건을 되돌릴 수 있어야 합니다.
- **Keyboard shortcut hint:** 단축키가 연결된 입력에는 일반 키보드 아이콘 대신 실제 키 문자를 24px 키캡으로 표시합니다. 키캡은 조작 요소나 별도 Tab 정지점이 아니며 Tooltip·Semantics로 의미를 전달합니다.
- **Icon action:** 새로고침·이전/다음·검색어 지우기·검색 닫기 같은 아이콘 단독 행동은 모두 48px 고정 조작면과 Tooltip을 사용하고 평상시 별도 표면을 추가하지 않습니다. 키보드 포커스에서만 사방 2px Focus Ring을 표시하며, 진행 중에는 같은 위치의 스피너·구체적인 live region·disabled 상태로 전환합니다.
- **Button focus:** Filled Primary는 Orange 면과 4.5:1 이상 대비되는 Ink 2px 경계를, Outlined·Text 행동은 Focus Ring 2px 경계를 사용합니다. 포커스는 면색을 추가하지 않아 선택·hover·pressed 상태와 혼동하지 않으며 Theme의 상태 토큰으로 모든 화면에 동일하게 적용합니다.
- **Preview source label:** 프리뷰 좌상단 칩은 현재 단계를 반복하지 않고 `라이브 카메라`, `촬영 이미지`, `선택한 이미지`, `카메라 미리보기` 중 실제 입력 출처만 표시합니다. `AppPreviewCopy`를 시각 문구와 `입력 미리보기, …` Semantics의 단일 소스로 사용합니다.
- **Camera preview:** 라이브 카메라와 촬영·선택 이미지 위에 흰색 테두리, 중앙 X, BIXOLON 대각선 가이드를 표시하지 않습니다. 촬영·분석 진행 피드백과 검출 bounding box만 기능적 오버레이로 허용합니다.
- **Selectable surface:** 선택되면 전체 면에 Brand Soft와 사방 1.5px Brand 외곽선을 표시합니다. 확정 후보처럼 값이 선택된 경우에는 radio/check, 객체·Activity처럼 현재 상세 대상을 가리키는 경우에는 화살표를 사용합니다. 왼쪽 띠는 사용하지 않습니다. pointer `tapDown`과 키보드 `ActivateIntent`를 구분해 동적 단계 전환의 포커스 인계는 Enter·Space 사용 시에만 실행합니다.
- **Candidate row:** Top-3와 전체 상품 검색 결과를 같은 60px 선택 행으로 표시합니다. 상품명을 우선하고 class ID와 confidence는 오른쪽 보조 정보로 낮춥니다. 현재 항목 번호와 선택 후 다음 항목으로 이동한다는 결과를 검수 영역에서 먼저 안내합니다. 검색 결과도 전체 면 hover·사방 포커스 링·단일 Semantics를 공유합니다. 레이블은 상품명·신뢰도만 읽고 버튼 역할과 tap 액션이 행동을 담당하며, Top-3·검색 결과는 보조기기에 상호 배타적인 단일 선택 그룹으로 노출합니다.
- **Step navigator:** 선택된 다중 객체가 있을 때만 `이전 | 현재/전체 | 다음`을 하나의 컨트롤로 묶어 표시합니다. 외곽선이 내부 조작 영역을 줄이지 않게 이전·다음 각각 정확히 48px를 유지하고 독립적인 포커스 링을 제공합니다. 항목이 하나이거나 선택이 해제된 완료 상태에서는 숨겨 최종 확정 행동과 경쟁하지 않게 합니다.
- **Detection box:** 모델 좌표의 시각 경계는 그대로 유지하되 클릭·Semantics 영역은 최소 44px로 확장합니다. 현재 검수 box는 항상 마지막에 그려 Brand 경계·저농도 면·`n 현재 검수` 레이블로 표시하고, 비선택 확정 box는 번호, 확인 필요 box는 `n ?`로 밀도를 낮춥니다. 전체 상태 문구는 결과 목록과 Semantics에서 제공합니다.
- **Activity row:** 확정 시각·상품 요약·입력원·`자동 확정/n개 수정`을 표시합니다. 처리시간처럼 현재 기록을 선택하는 데 필요하지 않은 진단 값은 목록에 노출하지 않습니다.
- **Diagnostic disclosure:** Activity 상세의 기본 깊이에는 확정 상품명과 수정 여부만 표시합니다. Scan ID·처리시간·모델 버전과 객체별 item ID·confidence·확정 방식은 하나의 접힌 `진단 정보`에서 제공합니다. 헤더는 60px이며 접힘·펼침 상태, chevron, 사방 포커스 링과 Enter·Space 실행을 함께 제공합니다.
- **Confirmation dialog:** 진행 중인 상품 확인 내용을 버리는 이미지 교체·재촬영은 400px 대화상자에서 질문과 구체적인 손실 결과를 먼저 설명합니다. `취소 | 실행 동사`를 같은 48px 폭의 행동으로 제공하고 안전한 `취소`에 초기 포커스를 둡니다. Tab으로 실행 행동에 이동하며 Enter로 현재 행동을 실행하고 Esc는 변경 없이 닫습니다. 중립 행동은 Focus Ring, Orange Primary는 대비가 보이는 Ink 포커스 링을 사용합니다.
- **Action bar:** 최소 72px의 고정된 표면에 화면 상태당 Primary action을 최대 하나만 배치합니다. 다중 검수에서는 같은 위치의 CTA를 유지하고 `남은 상품 확인 필요 → n개 상품 최종 확정 → 저장 중`으로 문구와 활성 상태만 전환합니다. 저장 실패 시 확인 결과와 FocusNode를 유지한 채 같은 위치를 `다시 저장`으로 전환해 키보드 Enter 재시도까지 완료 경로를 끊지 않습니다. 성공하면 실패 CTA를 제거하고 단일 완료 live region으로 확정을 알리며 다음 Tab 탐색을 새 작업 흐름에서 시작합니다. 진행 중 사용할 수 없는 Secondary는 회색 disabled 버튼으로 남기지 않고 숨기며, 실제로 계속 사용할 수 있는 카메라 연결 확인 중 `이미지 선택`만 유지합니다.
- **Progress action:** 시간이 걸리는 Primary action은 같은 버튼 위치·크기를 유지하고 진행 아이콘과 현재 동사로 전환합니다. 진행 중 버튼은 재실행할 수 없으며, 시각 문구보다 구체적인 단일 live region으로 `현재 작업 + 기다려야 하는 이유`를 알립니다.
- **Progress visual:** inline `20px`, preview `24px`, page `28px`의 같은 크기 슬롯을 유지합니다. 일반 환경에서는 회전형 진행 표시를 사용하고 reduced motion에서는 정적인 대기 아이콘을 사용합니다. 진행 시각 자체는 Semantics에서 제외하고 인접 문구 또는 단일 live region이 현재 작업을 설명합니다.
- **Toast:** 결과를 만든 행동의 완료 여부를 상단의 동일한 위치·형태·문구 체계로 3초 동안 알립니다. 스캔·Activity 전환과 무관한 전역 레이어에 표시하고 pointer 입력을 가로막지 않으며 단일 live region을 제공합니다. 연속 완료 시 이전 만료 타이머를 취소해 새 메시지의 전체 수명을 보장합니다.
- **Inline notice:** 기존 콘텐츠를 계속 사용할 수 있는 비차단 오류는 상태색의 저농도 면, 아이콘, 원인·현재 상태 문구, 선택적 보조 행동으로 콘텐츠 위에 표시합니다. 전체 오류 화면이나 Primary action으로 격상하지 않습니다. 같은 복구 행동이 툴바에도 있으면 오류가 유지되는 동안 툴바 행동을 숨겨 문맥 CTA 하나만 남깁니다. 키보드로 툴바 행동을 실행했다면 실패 시 인라인 복구 행동, 재시도 성공 시 원래 툴바 행동으로 포커스를 인계합니다. 진행 중 사용자가 다른 컨트롤로 이동하면 완료 후 포커스를 되가져오지 않습니다.
- **Loading state:** 아직 사용할 데이터가 없는 최초 로드는 작동하지 않는 도구를 숨기고 진행 표시와 `무엇을 불러오는 중인지` 설명하는 상태 레이블을 표시합니다. 기본은 단일 live region이며, 직전에 더 중요한 완료 알림이 있는 자동 동기화만 `announce: false`로 시각·접근 가능한 레이블을 유지하고 자동 발화를 끕니다. 기존 데이터가 있는 새로고침은 이 상태로 전환하지 않습니다.
- **State announcement:** 시각 화면을 추가하지 않고 완료 상태의 의미만 즉시 전달해야 할 때 `AppStateAnnouncement`를 사용합니다. 검수 중에는 현재 상품 제목 live region 하나를 유지하고, `APPROVED` 또는 마지막 상품 확인으로 모든 검수가 끝난 순간에만 `n개 상품 확인 완료. 최종 확정할 수 있어요.`를 알립니다. 화면 공간과 포커스·tap 행동을 만들지 않습니다.
- **State message:** `ERROR`·`RECAPTURE`·카메라 문제·Activity 빈/오류처럼 작업을 멈추거나 방향을 바꾸는 상태는 제목과 해결 설명을 하나의 live region으로 알립니다. 아이콘·제목·설명을 중복 발화하지 않으며 인접한 Primary 복구 행동은 별도 버튼 노드로 유지합니다. 검색·필터 결과가 없을 때는 편집 도구를 유지하되 상단의 중복 초기화를 숨기고 중앙 `모두 초기화` 하나를 Primary로 제공합니다.
- **Data row:** 60px 높이, 1px 구분선, 전체 선택 면, 보조 메타데이터 순으로 구성합니다.

### 선택 표면 상태

| 상태 | 면 | 경계·표식 |
| --- | --- | --- |
| Resting | Surface | 기본 구분선과 chevron |
| Hover | `rowHover` | 기존 경계를 유지하고 전체 면만 중립 hover로 전환 |
| Selected | `selectionSurface` | 사방 1.5px `selectionOutline`과 맥락별 radio/check 또는 화살표 |
| Selected filter | `selectionSurface` | 폭을 바꾸는 왼쪽 띠·체크 추가 없이 사방 1.5px `selectionOutline`과 Bold 레이블 |
| Focused | 현재 면 유지 | 선택 여부와 무관한 사방 2px `focusRing` |
| Disabled Primary | `disabledSurface` | `disabledContent`, 실행 불가 상태와 원인을 인접 문구로 표시 |

상태 우선순위는 `Focused border > Selected border > resting border`, 면 우선순위는 `Selected > Hover > resting`입니다. Hover는 마우스 사용자의 예측 피드백이며 동일한 기능은 키보드 포커스와 Enter·Space로도 사용할 수 있어야 합니다.

`AppSelectableSurface.inMutuallyExclusiveGroup`은 한 번에 하나의 현재 대상만 가질 수 있는 객체 목록·Top-3/검색 결과·Activity 목록에서 활성화합니다. 선택 상태는 `Semantics.selected`, 관계는 `inMutuallyExclusiveGroup`, 실행은 button·tap으로 분리하며 레이블에 `선택`을 반복하지 않습니다.

### 마이크로카피

- 사용자가 누른 행동과 확인 대화상자의 질문·확정 버튼은 같은 대상과 동사를 사용합니다. `AppActionCopy`의 `촬영하기`, `다시 촬영`, `분석하기`, `분석 중`, `다시 분석`, `다시 연결`, `연결 확인 중`, `새로고침`, `모두 초기화`, `저장 중`, `다시 저장`을 화면별로 변형하지 않습니다.
- 이미지 입력은 `다른 이미지 선택 → 다른 이미지를 선택할까요? → 다른 이미지 선택`, 카메라 입력은 `다시 촬영 → 다시 촬영할까요? → 다시 촬영`의 흐름을 유지합니다.
- 사용자 화면에서는 구현 용어인 `Worker` 대신 `분석 서버`를 사용합니다. `Scan ID`, 모델명, reason code, 상태 enum처럼 식별에 필요한 기술 용어만 영어로 유지합니다.
- 앱과 Windows 창의 제품명은 `BIXOLON Scanner`로 유지하되 화면 헤더는 BIXOLON 워드마크만 표시합니다.
- 질문은 결과를 먼저 알 수 있는 짧은 능동형 문장으로 쓰고, 되돌릴 수 없는 영향은 본문 한 문장으로 분리합니다.

## 화면 계약

### 스캔

- 지원 기준은 `1280×720` 이상이며 `1440×900`을 주요 검증 크기로 사용합니다.
- 결과 패널은 `AppDesignTokens`의 폭 비율 `36%`를 사용하되 `440~520px` 범위로 제한합니다. `1280px`에서는 `460.8px`, `1440px`에서는 `518.4px`로 실제 렌더되는지 위젯 테스트로 고정합니다.
- 프리뷰, 객체 목록, 선택 객체 검수, 고정 확정 푸터 순서로 정보를 제공합니다.
- 객체 목록은 실제 행 수만큼만 높이를 사용하고 선택된 행 바로 다음에 Top-3 또는 상품 검색을 이어 붙입니다. 객체가 많으면 검수 영역 `340px`를 먼저 확보하고 목록만 스크롤해 현재 행·선택지·대체 검색 행동을 한 화면에 유지합니다.
- Bounding box와 객체 목록 선택은 항상 동기화합니다.
- 프리뷰 번호는 `item_id`의 문자열 형식이 아니라 응답 배열의 표시 순서에서 계산해 결과 목록의 `01·02…`와 항상 일치시킵니다. 밀집·중첩 상황에서도 선택 box를 최상단에 그립니다.
- 프리뷰 출처 칩은 작업 단계나 결과를 반복하지 않고 사용자가 지금 보고 있는 입력이 라이브 카메라인지, 촬영 이미지인지, 선택한 이미지인지만 식별합니다. 단계와 검수 진행은 결과 패널 헤더·목록에서 제공합니다.
- 후보 확정, 목록 클릭, 방향키 이동으로 선택 객체가 바뀌면 결과 목록을 자동 스크롤해 현재 행을 항상 보이는 영역에 유지합니다. 이 이동은 판정이나 확정 상태를 바꾸지 않습니다.
- 선택된 객체가 둘 이상일 때 결과 헤더의 단계 탐색기는 현재 위치를 `n / 전체`로 표시합니다. 모든 객체가 확정되어 선택이 해제되거나 처음부터 단일 객체이면 탐색기를 표시하지 않습니다.
- 확정 푸터는 검수 중에도 사라지지 않으며 남은 수량을 표시한 비활성 CTA로 완료 조건을 예고합니다. 모든 상품이 확인된 뒤에만 동일한 CTA가 활성화되며 기존 제출 조건은 바꾸지 않습니다.
- `RECAPTURE`와 `ERROR`에서는 item 목록과 최종 확정 행동을 표시하지 않습니다.

상품명은 운영 카탈로그의 한국어 `display_name_ko`를 화면·Semantics·신규 Activity 로그에 사용합니다. 모델 계약의 영문 `class_name`은 API·진단·검색 호환성을 위해 보존하고 `class_id`와 함께 검색할 수 있지만, 사용자에게 보이는 기본 상품명으로 사용하지 않습니다. `display_name_ko`가 없는 카탈로그 항목은 조용히 영문으로 대체하지 않고 시작 시 형식 오류로 거부합니다.

공개 상태는 계속 `ERROR` 또는 `RECAPTURE`이며 Flutter 내부의 `ScannerErrorRecovery`만 다음 행동을 결정합니다. 입력 오류를 `RECAPTURE`로 바꾸거나 연결 오류에 재촬영을 요구하지 않습니다. 로컬 저장 실패도 Worker 상태를 바꾸지 않고 `reviewing`과 확정 결과·원본 입력을 유지합니다. 버튼과 복구 본문은 `다시 시도`처럼 모호한 표현 대신 실제 실행인 `다시 분석`, `새로고침`, `다른 이미지 선택`, `촬영 화면으로 돌아가기`, `촬영하기`, `다시 저장`을 사용합니다.

카메라 초기화·재연결·촬영 호출 실패는 Worker 응답이 아니므로 공개 `ERROR` 또는 `RECAPTURE`로 변환하지 않습니다. 내부 `CameraIssueType`은 장치 사용 불가 `unavailable`과 촬영 호출 실패 `captureFailed`를 구분해 사용자가 실제로 수행한 단계와 제목을 일치시킵니다. 촬영 실패는 `processState: ready`·응답 `null`을 유지하고 상단 배지·프리뷰·헤더·본문·Action bar를 `카메라 확인 필요`와 단일 `다시 연결`로 전환합니다. 재연결 Future가 진행되는 동안에는 `isCameraCheckActive`와 비활성 `연결 확인 중`으로 중복 실행을 막으며, 성공하면 라이브 카메라의 `촬영 준비`·`촬영하기`로 돌아갑니다.

### 활동

- 최근 100건에 대해 상품명/Scan ID 검색, 입력원, 기간, 정렬 필터를 로컬로 적용합니다.
- 저장 기록이 없거나 최초 로드가 실패한 상태에서는 `활동 기록` 제목만 유지하고 작동할 수 없는 검색·필터·정렬을 숨깁니다. 빈 상태는 `스캔 화면으로 이동`, 최초 오류는 `새로고침` 하나만 Primary로 제공합니다.
- 필터 순서는 `검색 AND 입력원 AND 기간`이며 그 결과를 최신순 또는 오래된순으로 정렬합니다.
- 수량은 상단 제목에서 반복하지 않고 목록 헤더에만 표시합니다. 기본 상태는 `n건`, 검색·입력원·기간 조건이 있으면 `표시 n / 전체 n건`과 `검색 결과`로 맥락을 함께 제공합니다.
- 검색어는 입력 필드에서 바로 지울 수 있고 검색·필터·정렬은 `모두 초기화`로 한 번에 기본값으로 되돌립니다. 일부 결과가 남아 있어도 초기화 행동을 숨기지 않습니다.
- 여러 상품이 포함된 기록은 목록에서 `첫 상품 외 n개`로 요약합니다. 상품명 검색 중에는 실제로 검색어와 일치한 상품을 첫 항목으로 올려 결과가 나타난 이유를 보여주고, 상세에서는 전체 상품을 저장 순서대로 표시합니다.
- 검색·입력원·기간 조합의 결과가 0건이면 검색창과 필터는 직접 수정할 수 있도록 유지합니다. 전체 검색·필터·정렬을 지우는 중앙 `모두 초기화`만 Primary로 제공하고 같은 행동의 상단 Text button은 숨깁니다.
- 목록은 확정 시각·상품·입력원·검수 결과만 표시하고, 검수 결과는 `자동 확정` 또는 `n개 수정`으로 즉시 구분합니다.
- 상세의 기본 깊이에는 확정 상품명과 `수정됨`만 표시합니다. Scan ID, 처리시간, 모델 버전, 객체별 item ID·confidence·확정 방식은 접힌 `진단 정보`에 배치합니다.
- 스캔 화면으로 이동해도 검색, 필터, 선택 기록을 앱 세션 동안 유지합니다.
- 최초 로딩은 콘텐츠 영역의 진행 상태로 표시하지만, 기록이 이미 있으면 새로고침 중에도 목록·선택·상세를 그대로 유지하고 새로고침 버튼 위치에서만 진행을 알립니다. 진행 중 추가 클릭과 `F5`는 새 요청을 만들지 않습니다.
- 기존 기록이 있는 새로고침만 실패하면 `새로고침하지 못했어요. 기존 활동을 표시하고 있어요.` 인라인 알림과 `새로고침` 하나를 제공하고 기존 목록을 유지합니다. 오류가 유지되는 동안 같은 툴바 아이콘은 숨기며 `F5`는 계속 작동합니다. 재시도를 시작하면 알림을 닫고 원래 툴바 위치의 진행 상태로 전환합니다. 최초 로딩 실패만 전체 오류 상태로 전환합니다.
- 정렬·필터·새로고침으로 선택 기록의 목록 위치가 바뀌면 해당 행을 자동 스크롤해 보이는 영역에 유지합니다. 선택 상세와 세션 상태는 바꾸지 않습니다.
- 긴 목록의 자동 스크롤은 `60px` 행 경계에 맞춥니다. viewport 높이가 행 높이의 배수가 아니면 나머지만큼 하단 buffer를 계산해 컬럼 헤더 아래 첫 기록과 마지막 선택 기록을 모두 잘림 없이 표시합니다.
- 기록 로드 오류 시에는 작동할 수 없는 검색·필터·정렬을 숨기고 상태 설명과 `새로고침` 행동만 노출합니다. 기존 필터 값은 재시도 후에도 유지합니다.

## 키보드와 접근성

| 키 | 동작 |
| --- | --- |
| `Ctrl+O` | 이미지 선택. 분석·저장 중에는 비활성 |
| `↑` / `↓` | 이전/다음 검수 객체 |
| `/` | 상품 또는 활동 검색에 포커스 |
| `Esc` | 검색 또는 활성 오버레이 닫기 |
| `F5` | 활동 기록 새로고침 |

- 텍스트 입력 중에는 객체 이동과 `/` 단축키를 가로채지 않습니다.
- 단축키의 가용성은 화면 행동과 같아야 합니다. 분석·저장 중처럼 이미지 선택 행동을 숨긴 상태에서는 스캔과 Activity 어느 화면에서도 `Ctrl+O`가 입력 선택이나 변경 확인 대화상자를 실행하지 않으며, 처리된 키로 가장하지도 않습니다. 카메라 연결 확인 중에는 실제 이미지 입력이 가능하므로 화면 버튼과 `Ctrl+O`를 함께 유지합니다.
- 촬영, 분석, 최종 확정에는 단축키를 제공하지 않습니다.
- 일반 텍스트는 최소 4.5:1, 큰 텍스트와 UI 경계는 최소 3:1 대비를 유지합니다.
- `1280×720` 논리 작업대에서 125%·150% 큰 글자를 지원합니다. Windows 150% 표시 배율의 `1920×1080 physical → 1280×720 logical` 환경도 동일한 레이아웃 계약을 유지합니다.
- confidence·처리시간·수량처럼 한 단위로 읽어야 하는 수치는 tabular figures와 줄바꿈 금지를 사용하고, 확대 시에도 `%`·`ms` 단위를 분리하지 않습니다.
- 포커스는 Focus Ring `#D96500` 2px 경계 또는 동등한 가시적 표시로 확인할 수 있어야 합니다.
- 선택 표면의 키보드 포커스는 선택 여부와 관계없이 사방 2px Focus Ring으로 표시합니다. 선택의 Brand Orange보다 약간 깊은 색으로 현재 키보드 위치와 선택값을 구분합니다.
- 마우스가 선택 가능한 전체 면에 진입하면 `rowHover`로 면을 전환하고 클릭 커서를 표시합니다. 이미 선택된 면은 hover가 덮지 않습니다.
- 상단 탐색은 `스캔 → 활동` 순서로 Tab 이동하며 Enter·Space로 실행합니다. Orange 돌출 탭은 `selected`, Deep Orange 전체 윤곽은 `focused`로 구분하고 둘 다 Semantics에 명시합니다.
- Activity의 Tab 순서는 `검색 → 검색어 지우기(입력 중) → 새로고침 → 입력원 필터 → 기간 필터 → 모두 초기화(활성 시) → 정렬 → 기록 목록`의 시각적 읽기 순서를 따릅니다. `AppFilterChip`은 포커스 시 사방 2px `focusRing`, 선택 시 1.5px `selectionOutline`을 사용하고 Space로 선택합니다. 정렬 드롭다운도 `AppDropdownControl`의 사방 2px `focusRing`으로 현재 위치를 표시합니다.
- Activity 필터는 화면의 그룹 제목에만 의존하지 않고 각 칩을 `입력원, 전체`, `기간, 전체`처럼 `그룹, 값`으로 읽습니다. 각 칩은 중복 없는 단일 Semantics 노드에서 `button`·`selected`·`focused`·상호 배타 그룹·`tap`을 함께 제공합니다.
- 검색이 비어 있을 때의 `/` 키캡은 `검색 단축키: /`로 읽히지만 Tab 정지점은 만들지 않습니다. Activity 도구는 명시적 순서 그룹을 사용해 검색 필드가 첫 Tab 위치를 유지합니다.
- 비차단 인라인 알림은 오류 문구를 독립 `liveRegion`으로 한 번만 알리고, 인접한 `새로고침` 같은 복구 행동은 별도 버튼·탭 노드로 유지합니다. 메시지 중복 제거를 위해 행동까지 `excludeSemantics`하지 않습니다.
- 전체 상태 메시지는 `제목. 해결 설명`을 하나의 `liveRegion`으로 제공하고 아이콘·시각 텍스트의 하위 Semantics만 합칩니다. `다시 분석`, `다른 이미지 선택`, `다시 연결`, `새로고침` 같은 복구 행동은 이 노드에 합치지 않아 독립적인 `tap`을 유지합니다.
- 선택 표면은 하나의 Semantics 노드로 노출하고 `button`·`selected`·`tap` 정보와 명확한 레이블을 제공합니다. 내부 텍스트와 InkWell은 중복 발화되지 않아야 합니다.
- 객체 행은 번호·상품명·확정 상태·confidence를, 후보 행은 상품명·confidence·선택 행동을 단일 레이블로 전달합니다. 현재 검수 항목 제목은 `liveRegion`으로 바뀐 번호를 알립니다.
- 검수 중에는 현재 항목 제목만 알리고 별도 진행 요약을 중복 발화하지 않습니다. 자동 승인 또는 마지막 상품 확인으로 검수가 끝나면 현재 항목 안내를 제거하고 완료 상태와 `최종 확정` 가능 여부를 하나의 `liveRegion`으로 알립니다.
- 단계 탐색기의 이전·다음 버튼은 실제 조작 영역이 각각 44px 이상이어야 하며, 가운데 위치는 `현재 n번 상품, 전체 m개`로 읽고 각 버튼은 `이전 상품 (↑)`·`다음 상품 (↓)`로 목적과 단축키를 함께 전달합니다.
- 프리뷰 box의 축약 레이블과 별개로 Semantics는 `n번`, 현재 선택 여부, 확인 필요 또는 확정 상품명을 모두 전달합니다. 작은 시각 box도 의미 영역과 포인터 영역은 44px 이상이어야 합니다.
- 포커스를 내부 InkWell에만 두지 않고 외부 단일 Semantics 노드의 `focused`에도 동기화합니다.
- 선택 표면은 마우스·터치와 동일하게 Enter와 Space로 작동해야 합니다.
- 후보 또는 전체 상품 검색 결과를 Enter·Space로 확정하면 다음 미확정 객체의 첫 후보로 포커스를 이어갑니다. 마지막 상품이면 같은 위치의 `최종 확정` CTA로 이동합니다. 마우스 클릭은 사용자의 포인터 위치를 존중해 포커스를 강제로 이동하지 않습니다.
- 완료 토스트는 `liveRegion`으로 즉시 알리되되 아이콘·문구가 별도로 중복 발화되지 않게 단일 레이블을 사용합니다.
- reduced motion이 활성화되면 선택 표면의 상태 전환 시간은 `0ms`가 됩니다.

## 반복 개선 체크리스트

각 개선 사이클은 아래 세 관점으로 같은 시나리오를 다시 사용한 뒤 기록합니다.

- **디자이너:** 위계가 3초 안에 읽히는가, 선택·포커스·상태가 서로 다른가, Orange가 필요한 곳에만 있는가
- **PM:** 현재 단계의 Primary가 하나인가, `APPROVED·UNKNOWN·RECAPTURE·ERROR` 계약과 실행 조건이 보존되는가
- **현장 사용자:** 마우스 이동이 짧은가, 1280×720에서도 잘리지 않는가, 다음 행동과 복구 방법을 설명 없이 알 수 있는가

검증 순서는 `준비 → 분석 중 → UNKNOWN 선택 → 최종 확정 → 완료 → Activity 검색·필터·상세 → RECAPTURE → ERROR`입니다. 매 사이클에서 발견한 문제는 먼저 토큰 또는 공통 컴포넌트에서 해결하고 화면별 예외는 마지막 수단으로 사용합니다.

`1440×900 UNKNOWN·선택 후보·단계 탐색 포커스·완료·상품 검색·상품 검색 빈 상태·상품 검색 포커스·Activity 목록·Activity 완료 토스트·Activity 검색 지우기 포커스·Activity 진단 포커스·Activity 진단 상세·Activity 새로고침 포커스·Activity 필터 포커스·Activity 정렬 포커스·Activity 오류`, `1280×720 카메라 확인 중·카메라 미연결 준비·카메라 사용 불가·카메라 촬영 준비·카메라 Secondary 포커스·카메라 Primary 포커스·카메라 촬영 실패·카메라 RECAPTURE·재촬영 라이브 복귀 포커스·촬영 중·재연결 진행·이미지 분석 준비·분석 중·APPROVED·저장 중·저장 중 검수 잠금·저장 실패 복구·완료 포커스·RECAPTURE·재분석형 ERROR·입력 교체형 ERROR·Activity 최초 로딩·Activity 최초 로드 오류·Activity 빈 상태·Activity 결과 없음·새 저장 동기화·새 저장 동기화 실패·상단 탐색 포커스·이미지 폐기 취소 포커스·이미지 폐기 확정 포커스·150% 재촬영 확인·8개 상품 자동 스크롤·밀집 프리뷰·20개 Activity 정렬·Activity 새로고침 중·비차단 새로고침 오류`, `1280×720 125%·150% 큰 글자의 UNKNOWN·Activity, 150% 카메라 촬영 준비와 125% 검색·초기화 상태`, 선택 표면의 Resting·Hover·Selected·Focused·Disabled 상태는 Pretendard와 Material Icons를 실제로 로드한 73개 골든 이미지로 검증합니다. 골든은 단순 업데이트하지 않고 디자이너·PM·현장 사용자 관점의 시각 비평 후에만 갱신합니다.


## 개선 이력

누적 변경 과정은 [디자인 시스템 개선 이력](docs/DESIGN_SYSTEM_HISTORY.md)에 보존합니다. 현재 구현 판단에는 이 문서의 계약을 우선합니다.

## 금지 사항

- BIXOLON Orange 위에 흰색 일반 텍스트를 사용하지 않습니다.
- 장식 목적으로 Orange 면, 대각선, 상태 배지를 반복하지 않습니다.
- 선택 가능한 객체·상품·활동 행에 왼쪽 띠만으로 선택 상태를 표시하지 않습니다. 하단선은 상단 탐색의 현재 위치 표시에만 사용합니다.
- 같은 화면에 서로 경쟁하는 Primary action을 두 개 이상 노출하지 않습니다.
- raw tensor, logits, 내부 예외, 로컬 경로를 UI에 표시하지 않습니다.
- `ERROR`를 재촬영 안내로 바꾸거나 `RECAPTURE`를 시스템 장애처럼 표현하지 않습니다.
